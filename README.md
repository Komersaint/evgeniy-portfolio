# Портфолио Евгения Наконечного — «Новая бумага» (Bento №3)

**Живая версия:** https://8jexonheohspt.space.mcode.io
**Исходный код:** https://github.com/Komersaint/evgeniy-portfolio

Персональный сайт-портфолио: приложение к резюме при поиске работы в AI/IT.
Многостраничный, статический, без внешних зависимостей в рантайме.

Стек: **Next.js 15 (App Router) + TypeScript + статический экспорт**, обычный CSS с
переменными — без Tailwind, без UI-кита, без анимационных библиотек.

---

## Запуск

```bash
cd ~/Work/evgeniy-portfolio
npm install
npm run dev      # http://localhost:4321
```

Другие команды:

```bash
npm run build    # сборка + статический экспорт в ./out
npm run start    # запуск собранной версии на :4321
npm run typecheck # проверка типов (tsc --noEmit)
```

Порт 4321 выбран, чтобы не конфликтовать с Vercel/Next на 3000.

## Как заменить портрет

Портрет уже стоит: это реальное фото Евгения, обработанное (фон заменён на студийный кремовый,
свет выровнен, кадр перекомпонован под карточку). Подробности — в `ИЗОБРАЖЕНИЯ.md`.

Чтобы поставить другое фото:

1. Положить файл в `public/images/portrait.jpg` (квадрат, 1000–1200 px, JPEG/PNG, до 1 МБ).
2. Обновить `alt` в `src/content/site.ts` → объект `portrait`.

Пропорции подстроятся сами: `object-fit: cover` в `.hero__portrait` (главная) и
`.about__portrait` (страница «Обо мне»). Если фото вертикальное и лицо смещено —
подправьте `object-position` в тех же правилах.

## Как добавить проект

Открыть `src/content/projects.ts` и добавить запись в массив `projects`:

```ts
{
  slug: 'novyy-proekt',        // адрес: /projects/novyy-proekt
  title: 'Название',
  kicker: 'Главный проект',     // подпись над заголовком
  index: '07',
  kind: 'case',                 // case | direction | product
  summary: 'Одно-два предложения — они попадут в обзор.',
  status: 'Работает · в продакшене',
  role: 'Моя роль в проекте.',
  problem: 'С какой задачи всё начиналось.',
  actions: ['Что я делал', 'Ещё один шаг'],
  result: 'Что получилось и что можно подтвердить.',
  stack: ['Python', 'n8n'],
  facts: [{ label: 'Тип', value: '...' }],
  statusNote: 'Честная пометка: чего пока нет.',
  image: '/images/novyy-obekt.jpg',
  imageAlt: 'Описание картинки для скринридера.',
}
```

Страница `/projects/novyy-proekt` создастся сама (маршрут `src/app/projects/[slug]/page.tsx`).
Отдельная вёрстка, как у Hermes и «Автоматизации», делается только если кейсу она нужна.

**Честность — обязательное правило.** Не выдумывать клиентов, даты, цифры эффективности и
ссылки. Чего нет — пишется в `statusNote`, на странице это видно как аккуратная рамка
«Честно».

## Как добавить запись в журнал

Открыть `src/content/journal.ts`, добавить запись в `journalEntries`:

```ts
{
  id: 'novaya-zapis',
  group: 'technical',            // technical | business
  title: 'Заголовок',
  date: 'Декабрь 2026',
  summary: 'Короткая выжимка.',
  situation: 'Что было.',
  problem: 'Что сломалось.',
  actions: ['Что я делал'],
  result: 'Что получилось.',
  lesson: 'Что вынес.',
}
```

Для черновика добавьте `draft: true` и `draftNote` — запись покажется с пометкой «Черновик».

## Почему ссылки обычные, а не next/link

Сайт собирается статикой (`output: 'export'`). При этом `next/link` перехватывает
клик и запрашивает RSC-файл вида `/<route>/index.txt`. На хостинге это ломается
двумя способами:

1. `.txt` отдаётся как `text/plain` — Safari такой ответ разобрать не может и
   показывает служебную ошибку с сырым RSC-пейлоадом вместо страницы.
2. На отсутствующий файл хост отвечает 404, отдавая главную страницу, — переход
   уводит на главную вместо нужной.

Поэтому `next/link` заменён на обычный `<a>` (`src/components/Link.tsx`): переход
делается обычной перезагрузкой, это не зависит ни от MIME-типов, ни от обработки
404 и одинаково работает во всех браузерах. Слеш в конце пути проставляется
автоматически: хостинг отдаёт `/about/` как каталог с `index.html`, а `/about`
без слеша уводит на главную.

Взамен мгновенного перехода роутера добавлено короткое появление страницы
(220 мс) — по ощущениям то же самое.

**Важно:** если будешь добавлять ссылки, используй компонент `Link` из
`@/components/Link`, а не `next/link`. И не вызывай `next/link` напрямую.

## Публикация

**Живой сайт:** https://8jexonheohspt.space.mcode.io
**Репозиторий:** https://github.com/Komersaint/evgeniy-portfolio

`npm run build` делает две вещи:

1. `next build` — статический экспорт в `out/` (18 страниц).
2. `node scripts/prepare-deploy.mjs` — собирает из `out/` чистую папку `dist/`:
   4K-оригиналы (22 МБ) убираются, добавляется `.nojekyll`. Именно `dist/` идёт в публикацию
   и в Vercel, и в GitHub Pages.

Локальный просмотр собранной версии: `npm start` → http://localhost:4321

### Vercel (свой домен и автодеплой)

1. Импортировать репозиторий в Vercel (или `vercel login` → `vercel --prod` из папки проекта).
2. Framework preset: **Next.js**, Node.js 20+.
3. Build command: `npm run build`, Output directory: `out` (Next сам соберёт; если задать
   `dist` — сборка уже будет чистой).
4. Переменные окружения не нужны.

После этого любой `git push` в `main` передеплоит сайт сам.

### Обновить текущую публикацию

Публикация живёт в диске платформы. После изменений: пересобрать (`npm run build`) и
передеплоить папку `dist/` — ссылка и адрес останутся теми же.

### GitHub Pages

В репозитории лежат готовые страницы в `dist/`, но Next.js-экспорт собирает абсолютные пути
(`/images/...`, `/_next/...`), поэтому для Pages нужен `basePath: '/evgeniy-portfolio'` в
`next.config.mjs` и префикс путей в контенте. Если Pages не принципиален — проще Vercel.
